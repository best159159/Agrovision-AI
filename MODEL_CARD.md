## Model Overview

AgroVision AI ships two complementary models that work together in an evidence pipeline:

| Model | Role | Architecture | Input |
|-------|------|-------------|-------|
| **Cassava Classifier** | Whole-image disease classification for cassava | EfficientNetV2B0 (fine-tuned) | 224×224 RGB image |
| **YOLO Crop Detector** | Multi-crop bounding-box detection (offline) | YOLOv8 (user-supplied `.pt`) | Arbitrary resolution image / video frame |

## Cassava Disease Classifier

### Intended Use
- **Primary use**: Field scouting support for cassava farmers and agricultural extension officers.
- **Secondary use**: Education and awareness of cassava disease symptoms in training programs.
- **Not intended for**: Sole basis for treatment decisions without agronomist confirmation; non-cassava crops; images taken under extreme lighting or from very close distance (< 10 cm).

### Classes (5)

| Index | Label | Disease / Condition |
|-------|-------|---------------------|
| 0 | Cassava Bacterial Blight (CBB) | *Xanthomonas axonopodis* pv. *manihotis* |
| 1 | Cassava Brown Streak Disease (CBSD) | *Cassava brown streak virus* (CBSV / UCBSV) |
| 2 | Cassava Green Mottle (CGM) | *Cassava green mottle virus* |
| 3 | Cassava Mosaic Disease (CMD) | *African cassava mosaic virus* (ACMV) and related begomoviruses |
| 4 | Healthy | No visible disease symptoms |

### Architecture & Training

| Parameter | Value |
|-----------|-------|
| Backbone | EfficientNetV2B0 (ImageNet pre-trained) |
| Input size | 224 × 224 px, float32, no explicit normalisation (backbone handles scaling) |
| Head | Global Average Pooling → Dense(5, softmax) |
| Fine-tune ratio | Last 10 % of backbone layers unfrozen during fine-tuning |
| Training phase 1 (head) | 3 epochs, frozen backbone |
| Training phase 2 (fine-tune) | 5 epochs, partial unfreeze |
| Batch size | 16 |
| Framework | TensorFlow 2.20 / Keras |
| Training environment | Google Colab (GPU) |

### Training Data

| Item | Detail |
|------|--------|
| Base dataset | Cassava Leaf Disease Dataset (Mwebaze et al., 2019 / Kaggle) |
| Source | Field images collected across Uganda and Tanzania |
| Known bias | Images skew towards East African cassava varieties; may generalise less well to Southeast Asian or South American cassava cultivars |
| Label quality | Crowd-sourced labels reviewed by plant pathologists (original dataset) |

> [!WARNING]
> **Geographic bias**: The training dataset is predominantly from East Africa. Accuracy may be lower on cassava images from Southeast Asia, Brazil, or other regions with different varieties and growing conditions. Independent validation on locally collected images is strongly recommended before deployment.

### Performance (Held-out Test Set — Internal African Dataset)

All metrics below were generated by `backend/evaluate_cassava.py` on a 2,000-image sample (400/class) drawn from the iCassava 2019 / Kaggle "cassava-leaf-disease-classification" pool — the same pool used in training. **No separately preserved, untouched split exists from the original training run, so this is not an independent held-out evaluation**, and is very likely optimistic relative to true generalisation performance. An external test on Southeast Asian cassava varieties has not been conducted.

| Metric | Value | Notes |
|--------|:---:|------|
| Overall Accuracy | **87.25%** | In-pool sample, n=2,000, class-balanced |
| Macro F1 | **87.32%** | Averaged across all 5 classes |
| Top-2 Accuracy | **95.70%** | Correct class in top 2 predictions |
| ECE (after temperature scaling) | **0.0712** | Temperature T = 1.138; higher (worse) than earlier unverified figure |
| Selective accuracy | **91.78%** | At 85.2% coverage (1,703/2,000 accepted, 297 referred) |
| Mean / P95 latency | 596.9 ms / 705.6 ms per image | CPU inference (no GPU available on eval machine) |

> [!CAUTION]
> **Validation package status**: These metrics come from a sample of the same pool used in training, not a geographically or temporally independent cohort. Per `RESEARCH_PROTOCOL.md`, a frozen external test cohort (e.g., Southeast Asian varieties, see `docs/thai-asean-cohort-plan.md`) is required before making deployment claims. Do not quote the 87.25% figure as a generalisation estimate without this caveat attached.

### Model Limitations

1. **Whole-image classifier only**: The model outputs a single class label per image. Lesion bounding boxes shown in the UI are produced by a classical HSV colour-thresholding heuristic (`estimate_cassava_lesion_regions`), **not** by the neural network. These regions are labelled `localization: estimated` in the API response and **must not be described as AI-detected lesions** in any scientific claim.
2. **Confident errors**: The most frequent error pattern (visible in `model/confident_errors.png`) is confusion between CMD and CGM with confidence 85–95%. This means the model can misclassify with high stated confidence — users must be informed of this risk.
3. **Confidence ≠ lesion severity**: The model's confidence score reflects classification certainty, not symptom extent. Confidence is never converted into severity. Visible area is reported only when the classical image heuristic finds candidate regions; otherwise it is `Not assessed`.
4. **Single crop**: The classifier was trained exclusively on cassava images. Uploading non-cassava crops will produce unreliable output.
5. **Image quality sensitivity**: Blurry, over-exposed, or under-exposed images, or images with excessive background clutter, degrade accuracy.
6. **No uncertainty quantification via Bayesian methods**: The softmax output can be over-confident. Shannon entropy of the softmax distribution is included as `uncertainty` in API responses. Temperature scaling (T=1.138) is applied.

## YOLO Crop Detector (Local Offline Model)

### Status
The default YOLO model (`backend/models/plant-disease.pt`) shipped with AgroVision is a **46-class crop classifier**. It identifies crop species (rice, tomato, cassava, etc.) from bounding boxes. **It does not currently detect individual disease lesions.** Detected boxes carry `diagnosisType: crop` in the API response.

To enable true disease detection, replace the default model with a YOLO model trained on labelled disease-lesion images (e.g., from PlantVillage or CGIAR datasets).

### Capabilities

| Feature | Supported |
|---------|:---------:|
| Crop-type detection | ✅ |
| Disease-lesion detection (bounding box) | ❌ Requires custom disease model |
| Video frame sampling | ✅ |
| Live RTSP drone stream | ✅ |
| Offline (no internet) | ✅ |

## Risk Scoring Model

AgroVision includes a **rule-based, explainable risk engine** (not a neural network). All formulae are documented in `TECHNICAL_VALIDATION.md`. Key properties:

- **Scan-level triage score**: an explicitly experimental prioritisation heuristic. It is not calibrated disease probability, severity, or forecast risk.
- **Environment-adjusted risk**: blends scan risk (70%) with Open-Meteo weather risk (30%).
- **Field-level risk**: incorporates severity, affected area, nearby outbreak count, and historical scan frequency.
- **Spread radius estimate**: disease-specific base radius scaled by field risk score and wind.

> [!NOTE]
> Risk weights are derived from epidemiological literature references listed in `TECHNICAL_VALIDATION.md`. They are **explainable heuristics**, not fitted ML parameters, and should be validated against local outbreak records before use in policy decisions.

## Ethical Considerations

### Human Confirmation
AgroVision is designed as a **decision-support tool, not an autonomous decision-maker**. Every diagnosis should be reviewed by a qualified agronomist or trained extension officer before a treatment is applied. The system flags this explicitly in the UI.

### Data Privacy
- Uploaded images are written to a temporary file and deleted immediately after analysis.
- Feedback images are not retained by default. Retention requires `STORE_FEEDBACK_IMAGES=true`; research exports additionally require an administrator token.
- Field and scan records are stored in a local SQLite database (`backend/agrovision.db`) under the user's control.
- Images are transmitted to Kindwise only when its cloud disease-screening key is configured. The OpenAI evidence assistant receives compact scan fields, not uploaded images, and does not create diagnoses.

### Consent and Ownership
- Users retain ownership of all images they upload.
- The system does not collect anonymised telemetry.

### Fairness and Access
- The offline-first design ensures that farmers in low-connectivity areas can use the core detection features without internet access.
- Risk formulas are fully documented to allow independent audit and regional recalibration.
